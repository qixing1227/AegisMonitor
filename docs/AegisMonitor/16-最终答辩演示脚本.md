# AegisMonitor 最终答辩演示脚本

## 1. 演示目标

在 10 分钟内证明课程设计级完整闭环：

~~~text
Windows Agent 采集并主动上报
-> Spring Boot 认证、接收、持久化和告警判断
-> MySQL 保存主机、服务、历史指标和告警
-> Vue 展示真实主机、性能趋势、服务组件和告警 ACK
~~~

演示以真实运行结果为主，Demo 数据只用于稳定展示服务组件和高 CPU 告警。

## 2. 答辩前检查

1. 确认 MySQL、后端、前端和至少一台真实 Agent 正在运行。
2. 确认 backend/application-local.yml、agent/agent.yml 未提交 Git。
3. 调用 Demo seed，确认服务组件和一条 OPEN 告警存在。
4. 浏览器提前打开 http://127.0.0.1:5173/hosts，缩放保持 100%。
5. 依赖和数据库提前准备，不在答辩现场执行安装。

快速自检：

~~~powershell
Invoke-RestMethod http://127.0.0.1:8080/api/agents
Invoke-RestMethod "http://127.0.0.1:8080/api/metrics/host/history?hostId=host_001&range=10m"
Invoke-RestMethod "http://127.0.0.1:8080/api/services?hostId=demo_host_001"
Invoke-RestMethod http://127.0.0.1:8080/api/alerts
~~~

准备 Demo 数据：

~~~powershell
Invoke-RestMethod -Method Post -ContentType "application/json" -Body '{"hostCount":3,"includeServices":true,"includeAlerts":true}' http://127.0.0.1:8080/api/demo/seed
~~~

## 3. 十分钟演示路线

### 3.1 项目定位与架构（0:00-1:30）

讲解：AegisMonitor 是一体化监控平台课程设计。Agent 部署在 Windows 主机上，采集 CPU、内存、TCP 和服务进程，通过 HTTP 上报 Spring Boot。后端使用 MySQL 保存业务数据和课程规模的历史指标，Vue 提供统一监控台。

强调当前是约 5 台主机的课程设计系统。InfluxDB、完整 RBAC、服务拓扑和通知渠道属于后续演进，不冒充已实现功能。

### 3.2 多真实主机接入（1:30-3:00）

1. 打开 /hosts，指出“真实主机”和“模拟主机”类型。
2. 展示至少两台真实电脑的主机名、IP、系统、规格和最近心跳。
3. 说明每台 Agent 首次注册后保存独立 agentId 和 agentSecret。

预期：真实主机为 ONLINE，最近心跳持续更新。

### 3.3 主机详情与历史趋势（3:00-5:00）

1. 点击真实主机“详情”，展示 CPU、内存、TCP 最新快照。
2. 展示“主机性能趋势”，切换 CPU、内存、TCP。
3. 切换 10 分钟、30 分钟、1 小时。
4. 停留约 5 秒，指出采样时间推进且页面不会整体闪烁。

讲解：历史点通过 HostMetricRepository 写入 MySQL；扩大规模时可增加 InfluxDB 适配器而保持前端接口不变。

### 3.4 服务组件（5:00-6:15）

1. 点击“服务组件”，选择 demo-web-01。
2. 展示 NGINX、进程、PID、端口 80、状态 RUNNING 和最后发现时间。
3. 说明 Agent 根据进程名、命令行和监听端口识别常见技术栈。

### 3.5 告警 ACK 闭环（6:15-8:00）

1. 点击“告警中心”。
2. 指出 demo_alert_cpu_high：当前值 93.5、阈值 80.0、CRITICAL、OPEN。
3. 点击 ACK，确认人填写 ops01，备注填写“已确认高 CPU 告警，扩容后持续观察”。
4. 点击“确认告警”，展示状态变为 ACKED，待处理数量减少。

### 3.6 工程质量与总结（8:00-10:00）

展示后端 26 项、前端 20 项、Agent 18 项测试，共 64 项通过；展示 GitHub Issues、PR review、文档体系和真实多机截图。

总结：我们完成了 Agent 纳管、真实主机采集、历史趋势、服务发现、告警生成和 ACK 的核心闭环，并通过测试、实机截图和 GitHub 记录证明系统可运行、过程可追溯。

## 5. 失败兜底

| 问题 | 处理方式 |
| --- | --- |
| 第二台真实电脑离线 | 展示真实双机截图，中心电脑 Agent 继续实时上报 |
| Demo 告警已 ACK | 再次调用 Demo seed，告警恢复为 OPEN |
| 服务列表为空 | 选择 demo-web-01 或重新调用 Demo seed |
| 后端无法连接 MySQL | 检查 MySQL84 和本地配置，不现场改代码 |
| 网络波动 | 先完成本机主链路，再展示多机验收截图 |

演示时不要打开本地配置，不展示数据库密码或 Agent Secret。
