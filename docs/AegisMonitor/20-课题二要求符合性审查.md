# AegisMonitor 课题二要求符合性审查

> 对照《广东公司提供实训课题2026年版》中的“课题二：一体化监控平台开发”，本文件用于说明当前项目是否覆盖课题要求，以及每项要求在系统中的落点。

## 1. 审查结论

当前 AegisMonitor 已达到**课程设计级可验收状态**：系统具备真实 Agent、多主机接入、主机指标采集、服务组件发现、指标入库、历史趋势展示、告警生成与 ACK 闭环等能力。对于课题中提到的完整企业级调用链、Spring Boot 深层运行时指标等能力，当前版本以“服务进程级指标 + 可扩展设计”覆盖课程展示要求，不伪造无法真实采集的数据。

## 3. 本轮补齐内容

本轮审查后补齐了两类原先偏弱的内容：

1. 主机指标补齐磁盘和网卡。
   - 后端新增 `disk_usage_percent`、`network_bytes_sent`、`network_bytes_received`。
   - 最新指标接口和历史曲线接口均返回这些字段。
   - 主机详情页新增磁盘使用率、网卡收发流量，并支持磁盘、网卡 RX、网卡 TX 历史曲线。

2. 服务组件从“只发现”提升为“可纳管”。
   - Agent 服务发现持续识别 Nginx、MySQL、Redis、Spring Boot、Node.js 等关键进程。
   - 后端保存服务名称、技术栈、进程名、PID、端口、运行状态和最后发现时间。
   - 服务组件页用于判断组件是否存在、是否仍被发现，以及所在主机和监听端口。

## 4. 当前边界说明

当前版本没有实现完整企业级调用链追踪，也没有接入 Spring Boot Actuator 获取活动会话数、HTTP 请求数、线程池等深层指标。原因是这些能力需要被监控应用主动开放 Actuator/Tracing 端点，或者接入 OpenTelemetry/Zipkin/Jaeger 等链路追踪体系，已经超出 5 人课程设计和少量真实电脑演示的合理范围。

答辩时建议表述为：

> 本项目在课程设计范围内实现了主机层和组件进程层监控。对于企业级深度组件指标和调用链追踪，我们在架构上保留扩展方向：后续可在 Agent 的技术栈识别结果上，为 Spring Boot 增加 Actuator 采集器，为微服务增加 OpenTelemetry/Jaeger 调用链接入。
